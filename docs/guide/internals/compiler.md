# Compiler pipeline

React Portal compiles components **on the instance**, in the platform's JavaScript engine, with no WebAssembly. The compiler (`src/server/compiler/compiler.ts`) is pure: no GlideRecord, so the same code could run in a browser or in Node. The build service (`src/server/build/build-service.ts`) wraps it with records.

```text
compilerInputs(owner)          main.tsx (client_script) + styles.css (css) + extra client/style files
      │
      ▼
link()                         walk the import graph from main.tsx; Sucrase each reachable file once
      │                        (typescript + jsx + imports → CommonJS-style module)
      │                        resolve: ./relative → bundled · react, @portal/runtime, components:*, utilities:* → host
      ▼
emitModule()                   one ES module: a tiny module table + loader, host lookups via
      │                        globalThis.__REACT_PORTAL__.modules; exports default + __rpExports
      ▼
extractCandidates()            class-like tokens from every reachable code file
compileTailwind()              Tailwind v4 compile().build(candidates) → moveVariantsToLayer()
      │
      ▼
index.js + index.css           CSS = Tailwind utilities, then styles.css, then imported .css files
      │
      ▼
resolveRecordImports()         components:<ns>/<key> / utilities:<ns>/<key> → target builds (build_dep)
applyCompileResult()           assets, deps, server script, snapshots replaced together; reprocess
```

## Version

`COMPILER_VERSION = 'rp-server-compiler/5 (sucrase <v>, tailwindcss <v>)'`. It's part of every component build's **input hash**, so a compiler change (or a Sucrase/Tailwind upgrade) marks every build out of date; each recompiles on its next compile.

| Version | Change |
|---|---|
| 2 | Compiler version enters the input hash; Tailwind arbitrary values fixed |
| 3 | Blocks, record imports (`__rpExports`) |
| 4 | Class extraction splits only outside `[]` (`group-data-[collapsible=icon]:hidden`) |
| 5 | Variant layer (`rp-variants`) |

The vendor bundles in `src/server/compiler/vendor/` (`sucrase.js`, `tailwind.js`, with Tailwind's CSS sheets inlined) are generated by `npm run vendor:compiler` (esbuild, ES2019, neutral platform). Regenerate after upgrading `sucrase` or `tailwindcss`.

## Transform

Each file is transformed by extension: `.ts` → typescript + imports; `.tsx` → typescript + jsx + imports; `.jsx`, `.js`, `.mjs`, `.cjs` → jsx + imports; `.json` → `module.exports = <json>`. JSX uses the classic runtime (`React.createElement`); the emitted module injects `React` into every file. Sucrase errors carry `(line:col)`, turned into diagnostics.

## Linker

- Starts at `main.tsx`; queues every `require()` Sucrase emitted.
- Relative specifiers resolve against the importing file's directory: exact path, then `.tsx .ts .jsx .js .mjs .json .css`, then `<dir>/index.<ext>`. Escaping the project root is an error.
- `.css` imports become `{}` in JS and are appended to the CSS in import order.
- Host specifiers: `react`, `react-dom`, `react-dom/client`, `react/jsx-runtime`, `react/jsx-dev-runtime`, `@portal/runtime`, and any `components:` / `utilities:` specifier. A missing host module throws at evaluation (`React Portal host does not provide "…"`).
- Anything else: `Unknown import "…"`.

Dependencies are recorded as `relative`, `host` or `component` (record imports, matched by `^(components|utilities):[a-z][a-z0-9-]{0,39}/[a-z][a-z0-9-]{0,79}$`).

## Record imports

After a successful link, the build service resolves each record import to its component's build and fails the compile if the target doesn't exist, is the component itself, is the wrong kind for the prefix (`components:` → primitive/widget/block; `utilities:` → utility), or has no usable build. Widget imports with a server script add a **warning** that the default export renders as an embedded instance.

## Tailwind

The input stylesheet:

```css
@layer theme, base, components, utilities, rp-variants;
@import "tailwindcss/theme" layer(theme);
@import "tailwindcss/utilities" layer(utilities);
@custom-variant dark (&:where(:host(.dark), :host(.dark) *, .dark, .dark *));
@theme inline { --color-<token>: var(--<token>); … --radius-sm…xl from --radius }
```

No preflight: the host's framework CSS provides it once. The colour tokens are the shadcn set plus `chart-1…5` and `sidebar-*`.

**Class extraction** is deliberately generous (Tailwind's own extractor is native code): split on whitespace and quotes, then on `{}<>=;\` outside square brackets, keep tokens of 2–160 characters that look like classes. Anything that isn't a utility is ignored by `build()`.

### Variant layer

`moveVariantsToLayer()` (`variant-layer.ts`, dependency-free string code) moves every variant rule out of `@layer utilities` into `@layer rp-variants`, except rules whose declarations are all `!important`. It handles Tailwind's nested output and the CLI's flattened, minified output. The host's `build:css` runs the same code on the framework CSS (`packages/portal-host/scripts/variant-layer.mjs`), and placement classes get it through `compileTailwind`. See [Styling](../authoring/styling.md#cascade-layers).

## Output module

`index.js` is a self-contained ES module:

```js
// React Portal compiled component: app/x (rp-server-compiler/5 …)
const __rpm = globalThis.__REACT_PORTAL__.modules;
function __rpHost(id) { … }
const React = __rpHost('react');
const __rpDefs = { "main.tsx": function (module, exports, require, React) { … }, … };
const __rpMaps = { "main.tsx": { "./parts/Row": "parts/Row.tsx", "react": "@host:react", … } };
function __rpLoad(path) { … }
const __rpEntry = __rpLoad("main.tsx");
export const __rpExports = __rpEntry;
export default (__rpEntry && __rpEntry.__esModule ? __rpEntry.default : __rpEntry.default || __rpEntry);
```

## Server script

`compileServerScript()` stores the author's script unchanged, wrapped so errors surface:

```js
try {
<author script>
} catch (__rpCaught) { __rpError = { message: …, line: __rpCaught.lineNumber || null } }
```

The author's code starts on line 2; the executor subtracts 1 from reported lines. `SERVER_SCRIPT_FORMAT` (4) is part of the input hash, so a format change recompiles everything.

## Input hash and skipping

The snapshot hashed into `input_hash`: extra files (path, target, content hash), the server script, hashes of `client_script` and `css`, `tailwind`, exports, options schema and defaults, dependency spec, theme tokens and stylesheet hash, the runtime ABI property, the server-script format and the compiler version. When a ready build already has that hash and ABI, the compile is skipped (`upToDate`).

## Themes

Themes don't go through the compiler: `theme.css` is stored as written (`rp-server-compiler/1 (theme passthrough)`), and tokens travel in the manifest.

## Async on the instance

Tailwind's `compile()` is asynchronous, so compiles return Promises. In scoped scripts Promise callbacks run when the outermost script finishes; REST handlers may return a Promise (`http.ts` writes the body when it settles), and business rules and exec scripts finish their compile at the end of the transaction.

## Dry runs

`POST /rp_studio/components/{id}/check` runs `compileComponent` over the saved project merged with unsaved buffers and writes nothing.
